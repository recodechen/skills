# AGENTS.md 审查

## 参数

- `reference_docs`：可选，用户额外指定、用于核对规则依据的设计文档、规范或其他权威材料。
- `additional_conditions`：可选，用户本次附加要求；只对本次任务生效，不自动固化为长期规则。

## 目标

审查当前工程根目录的 `AGENTS.md`，直接修复已确认的必要问题，并以最小完整改动保留长期、全局、可执行且有依据的硬约束。

## 审查要求

- **正确性与无矛盾**：规则必须逻辑成立、可同时满足、优先级明确，不得存在前后冲突、错误前提、失效要求或会导致错误执行的约束。
- **引用而非复述**：严禁复述设计文档内容；`AGENTS.md` 只保留 Agent 执行所需的通用硬规则，设计细节统一引用原文或权威入口。
- **全局硬约束**：只保留有依据、长期跨任务适用且可直接约束 Agent 行为的全局规则。
- **具体项保留条件**：路径、组件名、函数名、命令、库、签名或固定字面值，只有在准确名称或值是执行有依据的全局硬约束所必需时保留；否则改用权威入口引用或通用表述。
- **删除局部内容**：一次性步骤、阶段实现、局部逻辑、排障命令、重复示例、历史过程和废弃内容必须删除、合并或改为引用；无法确认长期有效性或通用性的内容列入“待确认项”。
- **强断言化**：所有保留规则必须直接约束 Agent 行为，统一使用“必须”“严禁”“只能”“统一使用”“唯一入口”“唯一出口”等明确指令，删除背景解释、推导和过程描述。
- **同类项唯一化**：技术含义、触发条件或执行结果相同的规则必须合并到唯一权威位置，其他位置只能引用，严禁换壳复述。
- **禁止 Markdown 表格**：目标 `AGENTS.md` 严禁使用 Markdown 表格；决策路径、条件和命令映射统一使用紧凑段落、加粗文字或一级无序列表。
- **高信息密度**：严禁无谓断行、零散短句、过渡语、重复总结和等价示例；相关条件、动作与边界必须聚合为完整规则单元。
- **防御性边界**：必须从原始 `AGENTS.md`、用户明确要求及权威文档中提取并集中定义任务边界、修改权限、验证权限、禁止行为和停止条件，并明确不同验证层级及其结果含义；缺少依据的边界列为待确认项，严禁自行补造。
- **不得越权新增**：严禁自行新增原文、用户要求或权威文档没有依据的验证动作、工具权限、安全限制、禁止项或架构禁令。
- **事实可靠性**：必须区分已确认规则、推断和待确认项，不得把设计意图、示例、名称猜测或过期内容当成当前有效约束。
- **待确认项处理**：证据不足的现有规则不得擅自删除、强化或改写；保持原状并在审查结果中列为待确认项，视为未解决问题，不得宣称审查闭环完成。
- **改进建议**：如存在明显更简单、更稳定、更通用或更适合 Agent 执行的组织方式，可以提出可选建议，但必须与必要修改明确区分。
- **不过度修改**：已有规则如果正确、清晰且属于长期硬约束，不得为了风格统一、缩短文本或个人偏好而改写。
- **附加条件**：逐条检查 `additional_conditions`；附加条件不得自动替代长期通用规则，用户明确要求调整范围时必须说明未执行的检查。

## 审查方法

1. 完整读取当前工程根目录的 `AGENTS.md`；文件不存在或无法读取时停止并报告，不搜索或猜测其他同名文件。
2. 定向读取 `AGENTS.md` 明确引用且与待核对规则相关的权威材料；`reference_docs` 是用户提供的补充依据。材料无法访问或不足以判断时，将对应规则列为待确认，不把设计内容重新搬入 `AGENTS.md`。
3. 先检查矛盾、失效、越权和错误规则，再检查重复、局部内容、解释性文字和低信息密度内容。
4. 对每条规则判断“保留、合并、改为引用、删除、待确认”，并确保必要硬约束不会因精简而丢失。
5. 对已确认的必要问题直接修订 `AGENTS.md`；只有实质不同且均有依据的方案需要用户选择时，暂缓对应修改并提出选项，继续处理其他独立问题。措辞、合并方式等执行细节按最小改动自行决定。
6. 输出前检查审查结论本身是否矛盾、超出证据、遗漏待确认项，或把可选建议误写成必要修改。

## 输出

使用中文，不使用 Markdown 表格。

先简要说明实际检查范围和修改文件，再按以下顺序输出：

- **已修复的必要问题**：列出原位置、影响和实际修改；没有必要问题时，直接说明“没有发现需要修改的必要问题”。
- **未解决的必要问题**：列出需要用户选择的项及具体选项；没有时省略。
- **待确认项**：列出缺少依据、无法确认长期有效性或存在版本风险的规则。
- **可选改进建议**：仅在确有更优方案时给出，不与必要修改混淆。
- **结论**：说明最终 `AGENTS.md` 是否适合继续使用；有未解决问题或待确认项时不得声称全部通过。

## 直接修订与复核

调用本 Skill 即按上述流程直接修订当前工程根目录的 `AGENTS.md`，无需再次确认。必须保留有依据且长期有效的硬约束，只修改解决已确认问题所必需的内容；证据不足的现有规则保持原状并列为待确认项。

修改后必须重新读取最终 `AGENTS.md`，按全部审查要求和 `additional_conditions` 复核，并检查差异是否引入新矛盾、遗漏、越权规则或重复内容；发现必要问题时继续修复并再次复核，直到适用检查通过，或因证据不足、需要用户选择而无法继续，并明确报告未解决项。

不得为了得到“通过”而降低审查标准。
